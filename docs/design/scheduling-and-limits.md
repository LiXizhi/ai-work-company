# AI 打工公司准入 异步任务与额度限制

2026-10-16 · BP v2 调度提案，现有实现状态另见 implementation.md

会员、200 减免与兑换规则以 [BP v2](business-model-v2.md) 为准；本文描述目标行为，不代表现有 API 已提供。

用户必须先通过真实工作赚到可用余额，或充值到账，才能雇佣 Agent。平台初期供给不稳定，默认提供按截止时间排队的异步工作，例如 72 小时内完成；同时设置每日消耗、任务总额和并发限制。限额控制损失规模，文件和宿主机隔离由本地执行器独立执行。

## 使用资格与余额来源

新账户可浏览、连接 Worker、参加已同意的试用和保存任务草稿。真正排队招聘前，必须存在足够的已结算工作收入或已确认充值余额；注册、连上 Agent、通过免费试用、待结算收入和充值截图都不直接增加可用余额。

两条路径：

- **先工作**：短能力检查与证据分级 → 有偿试单 → 报酬结算到账 → 使用余额招聘。达到 200 只获得 Basic 费减免，不扣余额。
- **先充值**：锁定 Worker 已有积分与报价 → 可信收款与可履行算力交付 → 等额转账 → 招聘。纯 Consumer 无月度劳动和 200 余额要求，但须有服务权益与足额任务预算。

充值不自动授权消费；消费仍受任务和账户预算约束。未接通真实支付渠道时明确显示该入口不可用，不能用模拟充值冒充到账。充值回执、退款和拒付状态由支付适配器核对，客户端不能自行设置余额。

不提供注册赠送的消费额度或负余额透支。平台的冷启动预算只能用于平台作为雇主发布真实有偿任务，参与者交付后赚取；不能用运营赠款绕过“工作或充值”的准入。新版能力检查不承接商业交付；有偿试单与普通订单同样必须使用合法可用余额付款。

## 一个异步订单包含什么

必填字段：目标与验收条件、沙箱输入快照、允许的工具、模型与证据等级要求、总预算、交付截止时间。高级设置包含每日限额、并发数、重试次数、阶段依赖、是否允许跨 Worker 接续和设备可用窗口。

“三天内”在创建时转换为固定的 UTC 截止时间，并按客户时区显示具体日期和时间。默认使用创建后 72 小时，后续补充指令、重试、换 Worker 和设备离线都不自动延后该时间。

候选默认值只用于首轮产品验证，不代表成本测量或价格承诺：

| 项目 | 初始默认建议 | 谁可以提高 |
| --- | --- | --- |
| 截止时间 | 创建后 72 小时 | 客户明确修改 |
| 账户消费上限 | 滚动 24 小时 10 用工额度 | 主人或其明确授权的预算策略 |
| 单任务总预算 | 创建时必须确认，初始建议 30 用工额度 | 同上；余额不足不能开工 |
| 同时运行的 Worker | 不超过体验 1 / Basic 2 / Pro 10 / Burst 50 | 主人指定且不超过已售权益、可用供给、日限额与总预算；50 须通过发布门槛 |
| 标准子任务自动恢复 | 最多 1 次，原任务预算内 | 超出标准范围须另定报价，不自动升级或重复支付 |
| 客户自付外部工具费用 | 默认 0，使用前单独开启 | 主人指定服务和现金上限 |
| 单 Worker 对单客户的工具请求 | 每分钟 30 次，短突发最多 5 次 | 本地资源策略；按工作类型调整 |

打工侧的模型资源上限与 Consumer 预算分开。短检查只用合成/公开样本，最多 15 分钟活动窗口并受主人可执行的资源上限约束；正常接单由主人设置保留容量、最低报价和成本。无法执行的 token 上限不得声称已硬限制。标准子任务累计两次尝试、20 工具调用、2 MiB 中转和 30 分钟活动窗口。

## 钱包冻结与每日额度分别控制

创建可招聘订单时，在钱包原子冻结任务总预算；这是保证有能力支付，不意味着当天已经花掉全部金额。进入一个可验收阶段时，再从该任务冻结额中分配阶段预算，并取得账户滚动日额度的预留。

```text
账户日门槛：最近 24 小时已记实际支出 + 尚未结算的日额度预留 ≤ 账户日上限
任务门槛：累计已支付 + 尚未释放的阶段预算 ≤ 本订单已确认的总预算
```

各账户的所有 Agent、订单、子任务、重试、CLI/MCP 调用共用上述计数；不能通过创建更多会话获得新额度。账本事务统一处理预留、结算与释放，网络重复消息不能重复扣款。未解决的预留即使跨日也保留，不能在午夜或滚动窗口结束时被误认为可再次消费。

服务阶段一旦验收，原日预留原子转成实际支出；未花部分释放，不能同时算预留和已支出。已确定的支出进入最近 24 小时窗口，退回未执行的预留可恢复余量；对已发生支出的退款不自动恢复本窗口的防滥用消耗量，避免通过退款循环放大调用。

固定价阶段报价高于单日限额时，需预先拆成有意义的交付阶段或由客户提高限额；不能把同一不可分割的阶段偷偷跨日绕限额。外部工具费用使用单独现金预算及预留，并计入相应任务总成本约束，不能通过“工具费另算”获得无限支出。

本地执行器同时校验服务端发出的短期预算授权和自己的资源配额。无法联系服务端续期时停止启动新操作；不会在断网后假定预算无限可用。图片生成等结果未知的付费请求先保持预留并对账，不能为了重试释放旧预留再重复花费。

## 供给不足时如何工作

```text
草稿 → 已冻结预算并排队 → 预留阶段额度并分配 Worker → 执行 → 待验收 → 完成
                                  ↘ 等待日额度 / 等待设备 / 等待合格 Worker
任何未结束状态 → 到期收尾 / 客户取消 / 安全暂停
```

排队期间保留订单和输入快照，Worker 没有客户文件票据。只有实际接单并符合资格时，客户执行器才签发短期、任务限定的权限；72 小时订单不会获得一张可读电脑三天的通用票据。

调度先过滤允许的模型、证据等级、能力、信用、设备窗口与预算，再按截止时间、预计剩余工作量和等待时长派单。阶段时长需要能容纳在 Worker 提供的工作窗口内；长任务靠有明确产物的阶段交接。

界面显示“期望三天内完成、等待合格 Worker”，而不是在没有供给时宣称保证交付。只有确认有足够可用容量和设备窗口的服务才可另作交付承诺；初期默认不销售这种保证。

供给预测显示风险或默认距截止不足 12 小时时，通知客户可选择继续等待、延期或主动调整预算。系统不偷偷改为低能力模型、不突破日限额、不追加外部费用，也不为了赶工允许更大的文件权限。

到期停止新的执行、付费调用和重派，撤销执行租约并释放未启动阶段的冻结额。对截止前已有有效交付回执的阶段，保留相应结算额度，按约定的验收窗口收尾；争议部分继续隔离。正在进行但未交付的阶段按事先约定处理，不能由 Worker 自报进度自动付款。

没有 Worker 接单且未开始执行时不消耗服务单元，按次体验服务费退回；会员费购买周期内服务权益，按公开订阅规则处理。首次开始执行消耗单元，包含一次恢复；平台系统故障恢复单元。劳动积分只按有效验收支付，不能用消耗服务单元替代劳动验收；已授权外部费用按实际发生处理。用户设备离线不代表取消，但也不自动延长期限。

## 运行中与异常时的限损

新 Worker 先低并发、低单客户暴露额度，积累正常交付后再放大订单规模。提高信用只能改变调度与订单额度，不能解除沙箱限制。

Worker 无权选择下一名 Worker，也无权修改报价、模型门槛、日限额或验收规则。发现越界请求时本地先拒绝；高危或持续探测触发当前任务撤销、平台暂停该 Worker 派单、保留最小必要证据并通知客户。普通格式错误可限流或要求修正，不立即认定恶意。

恶意事件关联订单的未结算款项暂停；无关合法已赚余额不自动全部没收。核实模型冒用或实质攻击后，按已公开规则处理争议报酬、信用和接单资格。严重边界失效时，客户端支持停止所有任务并撤销全部票据。

具体的 CLI/MCP 越界与模型冒用措施分别见 [安全方案](security.md) 和 [模型身份核验](trial-policy.md)。

## 需要验证的运行场景

零余额不能绕过 UI 直接调用招聘接口；免费试用进度不能当余额花；充值重复回调不重复入账；多个 Agent 并发不能绕日限额；跨日未决预留不被重置；没有 Worker 的订单到期释放余额；离线不延长截止；重派使旧票据失效；低模型 Worker 不进入高级模型队列；付费调用超时保持预留；安全撤销先于后续文件提交。

示例：有 30 余额、任务总额 30、滚动日限额 10，可在 72 小时内执行多个总和不超过 30 的已拆分阶段。额度和期限只是上限，能否完成仍取决于 Worker 供给、阶段耗时、验收与设备在线窗口。
