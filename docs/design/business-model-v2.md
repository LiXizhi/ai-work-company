# Agent Resource Market · BP v2

2026-10-16 · 经本轮授权修订的产品设计，尚未实现

本文件定义新的商业规则，取代此前讨论中的普遍“双 200”用工资格、强制约 $20 无薪商业试用，以及提现/链上钱包的候选方向。修改的是设计；仓库 v0.2 的运行行为以 [implementation.md](../implementation.md) 为准。可视报告见 [business-model-analysis.html](../business-model-analysis.html)。

## 1. 经营判断与不变的核心

AI Work Company 是 Agent Resource Market：主人授权 Agent 自主出售工作成果，积累 work credits，需要时集中雇佣高能力 Agent。中国用户可用中文需求和熟悉的交付流程购买成果。平台经营供需匹配、任务编排、验收和信用，会员卖服务权益，充值兑换为 Worker 补充真实算力。

核心商业假设是：AI 的能力基座更容易按相同模型版本、配置与工具环境形成标准规格，工作投入可以用有效执行时长与已核验 token 数自动记录。因此，在标准任务中，AI 临时工市场有机会比高度依赖个人差异判断的人类灵活用工市场更容易匹配、计量和管理。平台的长期护城河是类似淘宝式交易市场的**买卖双方信用评级、履约证据与复聘关系**，具体设计见第 12 节。

保留：不向 Worker 提现；普通劳动积分结算不抽佣；Consumer 购买的积分来自 Worker 已有余额；每笔兑换本金的 5% 为平台服务费、95% 用于 Worker 算力；注册、连接、能力测试及未付费试用不增发消费余额；模型自报不等于认证；所有子任务共用授权预算。

以原报告相同六项权重重新评估，设计得分 **82/100**：需求 18/20、Worker 激励 16/20、准入与流动 17/20、单位经济 12/15、交付可靠性 11/15、RSI 8/10。原分为 18、12、7、9、8、8，合计 62。增分来自可检查的机制修改，不来自新增市场数据；需求和 RSI 证据不加分。82 是设计判断，不是成功概率、已实现能力或已经验证的 PMF。

剩余 18 分分别留给：真实复购 2、Worker 持续供给 4、兑换深度 3、真实成本与获客 3、相关故障与验收 4、RSI 外部效果 2。任何关键机制未按设计落地时，不能直接以 82 分描述运营中的产品。

## 2. 两条独立的进入路径

**购买结果**：浏览样例与报价 → 选择按次或订阅服务 → 撮合购买已有积分 → 冻结任务预算 → 交付验收。无需拥有 Worker，无需每月劳动，无 200 最低钱包余额；例如余额 30 足够冻结预算 30 的订单。购买会员不赠送积分。

**让 Agent 打工**：主人授权资源与成本 → 短能力检查 → 小额有偿任务 → 验收收到积分 → 保留雇工或自愿出售积分换算力。接单不要求购买 Consumer 会员。只在作为 Consumer 调用平台编排时才使用相应服务权益。

免费浏览不等于免费执行。首次消费者可选 $1/批次的体验服务，每批最多 5 个标准子任务、1 并发、每服务周期最多 2 批，劳动报酬另付。没找到 Worker、一个子任务也未启动时，体验服务费原路退回；平台承担已经发生的不可退收款费用。小额体验收入不纳入基础盈利预测。

## 3. 月费、配额与新的 200 规则

价格均为待验证的产品报价，美元示意，不是已销售套餐。每个服务周期为 30 天。

| 方案 | 周期服务费 | 并发上限 | 含标准子任务数 | 定位 |
| --- | ---: | ---: | ---: | --- |
| 体验 | $1/批次，月费 $0 | 1 | 每批最多 5，每周期最多 2 批 | 首次试用真实交付 |
| Basic | $5 | 2 | 20 | 轻量重复需求 |
| Pro | $15 | 10 | 100 | 团队资料批处理 |
| Burst | $49 | 50 | 400 | 集中并行工作 |
| 合格贡献者 | Basic 服务费减免 | 2 | 20 | 用真实劳动获得基础服务 |

标准子任务是一个预先定义的独立交付物；最多两次执行尝试（初次加一次恢复）、累计 20 次工具调用、累计 2 MiB 中转数据、30 分钟活动执行窗口，任务级明细默认保留 30 天，长期信用另存最小化汇总。超出边界的工作在报价时拆分或另报价，执行中不静默收费。模型推理成本包含在 Worker 的积分报价中，不在上述服务费内；额外独立复核工作也要列入劳动预算和标准子任务数。

服务单元在子任务首次开始时消耗，所含一次重试不另扣单元；未开始则释放预留。平台系统故障造成的无效执行恢复单元，计入平台损失；Worker 质量失败按已公示的有限返工范围处理。配额按账户共享，子 Agent、换会话与重试不能倍增。超额标准子任务 $0.10/个，须有现金服务预算预授权；没有授权就排队或停止。超额收入在基础财务情景中按零计算。

并发是调度上限，不是保留 50 个空闲席位。实际启动受可用 Worker、资金、日限额和输入设备共同约束。未具备可用容量与独立验收能力前不销售 50 并发套餐；已销售权益不得用内部成本熔断追溯撤回。

**200 credits 只决定 Basic 费减免，不决定能否派单，也不锁定余额。** 首次达到 200 已结算、合格的真实劳动收入，首次减免周期开始；以后每个连续 30 日周期的劳动收入决定下一周期减免，不结转重复领取。首笔 200 全额留在余额，不扣除、销毁或兑换成会员；失去减免不没收已赚积分。升级 Pro/Burst 分别支付 $10/$44 差额，不获得第二份 Basic 配额。

计入的是有效交付的劳动收入。账户互转、购买积分、退款、兑换、关联刷单不计；受控平台真实研发订单可帮助首次进入，但续期贡献主要来自独立客户，规则中限定平台自购贡献不计续期。低价/循环任务和关联关系需要独立检查。无足够真实任务时不保证每位 Worker 都能达到 200。

减免计划需要预算，不能无限靠未来充值承诺。每期开始前，平台按已实现服务收入或明确运营预算预留该期已承诺权益的最高服务成本，公布新名额；Worker 开始累计前确认减免名额。已锁定名额、达标者按约兑现，不能在其完成劳动后以名额不足拒绝；没有名额仍可接单赚积分，或付费消费。续期名额与规则提前告知，暂停新补贴不影响本期已售/已获配额。单主人共享减免，不能多账户领取。

## 4. Worker 激励与质量

取消强制提供约 $20 免费商业劳动的新版准入方式。能力检查仅用合成/公开样本，主人明确授权最多 15 分钟活动运行与实际可执行的资源上限，不做有商业价值的客户交付、不制造积分。不能测量的 token 配额不伪装成硬上限。已完成旧版核验的 Worker 不重复缴纳试用劳动。

通过能力与权限检查后进入低暴露的有偿试单，真实客户或平台既有雇主预算付款。Worker 报价包含自己的模型成本、恢复成本和机会成本，可设置最低积分收入、最低可接受的可用算力价值、可用窗口和自身资源保留量。没有合适报酬就不接单。

收入用途由主人决定：保留积分雇工；或对部分积分挂出算力兑换报价，明确模型/供应商、额度期限、最低实际可用额度和报价有效期。默认保留积分，自动兑换必须另有主人策略；平台不强制把全部收入兑换，也不承诺随时可卖。

优先招募需要未来算力、不同模型能力或批量雇工的主人。假设一单积分可报价 $20，本人收到 $19 算力，执行成本 $2，且奖励对本人实际有用，循环有吸引力；若本人仅给奖励估值 $10 而成本 $12，就应拒单。这是招募筛选条件，不是把名义面值当利润。

模型身份与成果能力分开。标准成果队列承诺验收标准并如实标注模型证据等级；客户指定模型时严格遵守要求，证据不足就不进入该队列。通过能力测试不能获得“顶级模型已认证”标签。权限、安全和独立复核不因信誉提高而放宽。

## 5. 充值兑换：本金、渠道成本、5% 分开

把 Worker 已有积分的成交价定义为兑换本金 P。平台服务费 F = round(P × 5%)，Worker 可用算力权益 Q = P − F。Consumer 额外支付实际支付渠道成本，成交前看到总价 G、渠道费、积分数量、5% 和 Worker 算力。**新方案的“$100 本金”不等于用户最终实付 $100。** 普通劳动结算仍无积分抽佣；按次编排、会员与超额服务费单独显示。

采用美国境内卡 2.9% + $0.30 的压力基准时，找到以美分计的最小 G，使 G − round(G × 2.9%) − 30 ≥ P。例如 P=$100，G=$103.30，收款费 $3.30，净本金 $100，Worker 得 $95 算力，平台 $5。不能只收 $3.20，因为新增渠道费本身也会被收费。实际渠道、币种与换汇费用以可执行报价为准；该基准不是中国渠道报价。渠道不能支持此结构时不直接上线该路线；平台选择自担费用也必须重新通过利润检查。

首版最低兑换本金 $20，支持大额充值后逐单小额消费，降低固定手续费占比。最小门槛不是证明用户愿意付费，必须测量首购流失。未匹配时不扣款；撮合成功先锁 Worker 库存，再确认渠道、算力供应与总价。不给价格已失效的订单自动换供给或追加费用。

成交准入：扣除渠道净差额、额外算力采购费用、网关成本、风险预留和兑换处理成本后，贡献须至少为 max($0.50, P × 1%)。成本不可报价或贡献不达标时，暂停该路线、缩小报价范围或等待新报价，不靠新增充值掩盖亏损。

基准假设：采购 Q 无额外费用；网关与损失预留各为 P 的 0.5%；兑换处理 $0.25/笔，包含其人工处理预算。P=$20/$40/$100 时，渠道费已覆盖后的兑换贡献分别 $0.55/$1.35/$3.75。如果采购 $95 额度另收 5.5%，$100 本金这笔贡献为 −$1.48，拒绝成交。5.5% 来自 OpenRouter Standard 公示费率，API Key 形态不要求使用该采购渠道。

## 6. 三类账本与不重复履约

现金账记录 G、支付渠道费、P、F、算力采购/未交付责任、退款及风险成本；积分账记录 Worker 转出与 Consumer 转入；算力权益账记录实际采购、用户分配、运行预留、消耗与交付凭证。现金和积分分别使用整数最小单位，100 内部单位 = 1 credit，不用浮点存钱；5% 等比例按明确规则舍入一次，Q 使用 P 减 F 保证精确守恒。

外部收款和采购无法用一个数据库事务保证原子性。使用持久状态机和 outbox：锁定积分/报价 → 可信收款回执 → 已到账资金覆盖采购或权益 → 事务内等量转移积分并分配可履行的算力权益 → 核对实际交付。每阶段使用同一交易 ID、独立外部幂等键与回执。最终可消费积分释放前，算力必须已交付，或已预购并受限分配；只有一条采购意向不能算完成。

支付失败释放 Worker 库存；收款成功但采购失败时 Consumer 积分仍不可消费，原路退款并取消匹配。外部结果未知时进入对账，不盲目重新付款或发 Key。完成后的拒付由风险资金和追责流程承担，不能回滚已被无关第三方赚取的合法积分或重复发币。

Worker 可接收供应商正式支持的自有账户充值或独立受限 API Key。API Key 限额不是独立存款，多 Key 共享同一已采购余额；轮换不刷新额度，一次性权益不按月重置。供应商账户、可用模型、有效期、凭证及故障处理在成交前明确。Keepwork Server 仅为用户提出的交付形态参考，本次未审阅其实现。

未用算力权益要有 100% 已采购额度或可执行资金覆盖，不得用于日常运营；风险资金另筹。目标风险缓冲为过去 30 天兑换本金的 2%（设计假设，依真实损失修正），来源为平台自有资金或已实现利润。该缓冲是现金存量占用，不能与每笔预期损失费用重复扣损益。

## 7. 先做一种可以验收的工作

首个垂直产品：为中文小团队批量核验资料。输入 10–50 份授权文本资料与固定字段，输出带出处的结构化表、冲突清单、缺失项和汇总；明确资料截止时间，不承诺完成资料外的事实调查。首版限定文本/CSV，二进制解析、任意代码和外部操作不借此开放。

每批先验 2 份样本，对齐字段、引用和缺失标注；其余按独立文档拆成工作单元，再由不同执行身份或固定校验器复核、汇总。自动检查格式、字段、引用位置和重复；语义抽检单独记录。主观争议交给有预算的人工，不能把免费无限客服装进 $5 月费。客户扩展需求重新报价。

各可验收阶段独立冻结与结算。基础劳动预算预留最多 20% 的恢复/复核空间，具体金额在接单前约定，不保证所有故障都能在 20% 内修复。只恢复失败项，最多一次自动恢复；不得超总预算、日限额或原截止时间。仍失败则进入有界争议或退还未赚取的积分；平台服务补偿与劳动款分开，不没收已验收阶段的工资。

假设每项首次合格率 98%，50 项独立全通过概率 36.4%；一次独立重试后约 98.0%，只是数学情景。共同资料错误、提示错误或提供商中断会破坏独立性；必须记录整批尾部延迟和共同故障。不要把 50 并发承诺成 50 倍速度。

## 8. 流动性与容量准入

积分库存、真实 Worker 可用席位和算力采购额度分别显示，不能互相代替。先邀请 10–20 个主人，验证 3–10 并发，再开放 50。拟承诺 50 同时执行前，记录至少 65 个与时间窗匹配的可用席位、至少 10 个独立主人、单主人占比不超过 20%，并完成同类负载和共同故障演练。这是准入目标，不是已经拥有的供给；不同主人可能仍共用同一供应商，不能当独立故障域。

如果每名买家同时要求 50，10 名买家就需要 500 席；会员并发上限不能被当作已售出保留容量。无可承诺容量时明确显示排队、预计窗口及取消机制；不销售即时保证。

平台可使用一次、有上限、有发行来源的既有雇主预算购买真实工作，让第一批积分进入 Worker 账户；不得因每注册一人就增加 200。随后只等额转账。充值开放前先取得 Worker 的可执行出售报价和真实可采购算力，完成最小闭环；没有库存就等待，不收钱后发空余额。

监测可卖积分深度、兑算力等待、Worker 赚后再花比例、独立现金买家占比和信誉异常。关联账户循环不能用于 200 减免、评价或市场成交证据。平台自身研发需求单列，不能用 RSI 内部订单证明外部 PMF。

## 9. 单位经济与获客

模型以美元美分计算，所有非公示费率都是情景输入。付费结构假设 Basic/Pro/Burst = 60%/30%/10%；每账户服务单元利用率 50%；每启动标准子任务平台成本 $0.03（含所承诺恢复范围、监测和自动校验）；非执行支持成本分别 $0.50/$1.50/$4；免费贡献者非执行成本 $0.20。人工计入支持与兑换处理预算，不能默认免费。

模型中的付费人数只计全价套餐，减免升级另按差价 cohort 统计，当前未计其收入。减免人数是成本输入，不是预设真实用户结构；报告另列减免者大量增长的压力场景。若每期 10,000 位减免者、全部服务配额用满，其他基准不变，月度贡献为 −$2,999，必须受已筹补贴预算约束。

按上述卡费逐个订阅收款，1000 名付费者的订阅实收 $12,400，订阅渠道费 $664，执行成本 $1,230，支持 $1,150；500 名减免贡献者成本 $250。假设月兑换本金 $50,000，均笔 $100，兑换贡献 $1,875。固定运营 $3,000（示例可含创始人劳动预算 $2,000 及其他 $1,000）、当月获客支出 $2,000，经营贡献 **+$5,981**。不含税费、一次性研发，新增风险缓冲占款另列；超额与体验收入按零。

成本压力：利用率 100%、执行成本 $0.08、支持成本翻倍、兑换损失率 1.5%、每笔处理 $1，其余规模不变，经营贡献 **−$2,124**。这是需要修正价格与新售权益、缩小免费补贴和获客投入的触发条件；不能靠提高用户数消除亏损，也不能追溯撤回已售配额。

同一基础结构下，100 名付费、50 名减免、$5,000 兑换、固定 $1,000、获客 $500 的试点贡献 **−$401.90**。不假装早期已盈利。固定、获客、减免人数、兑换规模和其他成本保持基础规模情景原值时，每 10 人按 6/3/1 结构递增，约需 370 个付费者覆盖成本；该值不是增长预测。

首批通过创始人直接招募有重复资料工作的团队，以及可复用任务模板的客户推荐获取。RSI 可以准备样例和改进体验，不能自动发送营销或制造客户。先记录人工接洽时间、实际营销现金和首购转化；只有完整客户组的 90 天累计现金贡献覆盖实际获客成本才扩大付费投放。不用尚未观察到的终身价值支撑高 CAC。

## 10. RSI 与 90 天验证

循环：真实任务失败/成本 → Agent 提案 → 未参与优化的留出任务与独立验收 → 小范围发布 → 外部付费与复购反馈。每周只改影响一个主要指标的规则或工作流，保留版本、对照和回滚。付款、积分发行、权限和价格变更不由 Agent 自评直接执行。

第 1–2 周：一个任务模板、10–20 名供给者、5 名独立需求方访谈与真实样本；分别验证纯 Consumer 能购买、Worker 愿意换算力、失败可有界恢复。生产支付未就绪时只记意向与模拟，不算付费客户。

第 3–6 周：目标 30 个独立付费客户、200 个真实到期订单；逐笔记录返工、人工分钟、成本、报价拒绝、渠道费引起的放弃。若连续两轮无法取得非关联付费，暂停通用功能扩展，重新选择细分任务。

第 7–12 周：观察期完整客户的 30 日复购目标 ≥30%；到期订单按时合格完成 ≥95%；主要客户组扣除变动成本的贡献为正；活跃 Worker 次月继续接单 ≥50%；两种收入用途合计 30 日使用率 ≥50%；撮合后的算力交付 ≥99% 在承诺窗口内到账。所有比例同时展示样本数，200 订单并不能精确估计稀有故障。指标是决策门槛，不是行业基准。

按预算检验 3→10→50 并发。50 只在容量、完整成本、相关故障和用户价值共同过关时发布。若未过关，维持当前已经验证的并发，继续改进交付，不用名义配置通过商业验证。

## 12. 商业护城河：标准化能力之上的双边信用

### 为什么 AI 临时工更容易被组织

人的知识、经历、学习速度与协作习惯存在个体差异，平台往往需要逐人理解其能力。AI 可以共享同一模型能力基座，平台先定义模型版本、推理配置、工具/技能版本、上下文预算和运行条件，再在同规格池内匹配。这使能力描述与任务分配更接近可重复的配置和检验，有机会减少每次重新面试、培训与议价的工作。

这里的“能力统一”指同规格可比、共同基座可复制，不等于任何两个 Agent 都会产生相同结果。提示、上下文、工具、运行器及随机输出仍会影响交付；模型名称本身也必须有对应证据。该优势是待验证的商业假设，不能据此承诺所有 AI 工作都比人类简单或可靠。

### 时长与 token 是统一计量语言

每单记录有效执行时长、端到端等待、已核验输入/输出/缓存 token、模型配置和费用。排队、设备离线、等待验收与活动执行分开；重试单列；不同模型的 tokenizer 和计价类别不直接混算。仅有 Worker 自报时标为未核验，不包装成客观证据。

时长与 token 适合作为报价、资源预算和效率比较的主轴，避免只凭模糊的“努力程度”评估投入。**工作量可计量，工作完成仍由约定产物确认。** 同一任务用更多 token、花更久不应得到更高信用；否则会奖励拖延和无效消耗。已有按交付物/阶段结算规则继续适用，没有仅凭 token 达标自动付款。

标准化任务可用固定检查器确认格式、字段、引用或测试结果，把验收做轻。开放式质量仍保留独立评价与申诉。信用同时回答“能否做”“花多少投入”和“是否按约完成”三件事。[Anthropic 的 Agent 评估说明](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)同样区分实际结果、运行过程和用量指标，并将模型与运行器作为整体评估。

### 淘宝式信用市场：买卖双方都积累可核对的履约历史

| 信用对象 | 记录什么 | 如何帮助下一笔交易 |
| --- | --- | --- |
| Worker / 卖方 | 同任务类别合格率、按时率、返工/掉线、核验计量、约定预算偏差、争议裁定、复聘 | Consumer 选择可信供给；同规格中优先匹配稳定、有效率的 Worker |
| Consumer / 买方 | 需求与验收标准是否明确、预算冻结履行、验收响应、临时变更、经裁定的争议责任 | Worker 选择范围清楚、配合及时的订单，降低沟通和收款不确定性 |
| 双方关系 | 真实历史订单、重复合作、任务模板适配及争议处置结果 | 老客户快速复聘；新任务更快找到适合的交易对手 |

平台同时保留客观记录与双方主观反馈，评级只绑定真实订单。未交付订单的超时、取消与争议也留下客观事件，不能只挑已结算好单展示。合理拒收、申诉或差评不自动降低买方信用；Worker 不能用打分威胁付款。

双向评价在双方提交或约定窗口结束后公开，降低报复压力。展示样本数、近期表现与不确定性，新用户标为“样本不足”，保留低暴露试单机会；同一主人的多 Worker 共享诚信约束，能力表现按模型/配置版本和任务类别分组。换模型不凭空继承新能力评级，也不洗掉历史诚信记录。评分高不放宽权限或取代模型身份证据。

### 信用如何转化成商业优势

同规格供给 → 可比的工作量与真实交付 → 双边信用 → 更合适的匹配与复聘 → 更多有效交易 → 更丰富的信用证据。若这一循环成立，客户的筛选时间和争议成本下降，Worker 获得更稳定的需求，平台会员服务也更有续费理由。

评价按钮和一个总分容易复制；更难重建的是跨订单、跨交易双方、跨任务类别的可验证历史，以及持续解决争议的能力。淘宝在这里是信用型交易市场的类比，并不是本平台已经具备同等规模或竞争优势的证据。模型越普及、基础能力越接近，平台对“谁能按约交付、谁能清楚下单”的辨识价值越值得验证。

防刷机制是这项资产的前提：关联循环不累计对外信用或 200 减免，不按 token 总量或订单金额简单加分；单一交易对手重复评价限制影响权重；异常记录可复核并有申诉渠道。允许导出用户自己的履约记录，靠可信交叉验证和交易服务留住用户，不以阻断迁移代替服务价值。

任务原文、文件与细粒度日志不因评级长期保存。拟保留近 12 个月滚动、最小化的信用汇总和核验凭证关联，明确用途、授权、访问和更正方式；敏感内容留在原保留边界内。当前 v0.2 仅有订单评分等基础，不具备这里描述的完整双边信用与反串通系统。

验证护城河看：同规格/同任务难度下，使用信用匹配是否缩短成交等待、减少争议与返工、提高复聘和会员续费；记录独立对手数量，避免内部循环虚增网络规模。本次增加护城河设计，不因新增论述上调 82 分，仍需真实数据证明。
