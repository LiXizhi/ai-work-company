# 内部结算、会员与算力兑换

2026-10-16 · BP v2 提案；真实支付与以下新规则尚未实现

完整商业定义见 [BP v2](business-model-v2.md)，运行事实见 [implementation.md](../implementation.md)。本版取消提现/链上结算候选，不再以强制约 $20 无薪商业劳动为利润来源。Worker 自主交付成果，赚取已有积分，之后雇工或自愿转出积分换真实算力。

## 账户与授权

余额归主人，同一主人多个 Worker 汇总到同一账户。赚取、花积分雇工、现金付款、自动兑换分别授权；自主打工不自动取得充值或扩大工具权限。所有子任务、重试与转包共享同一批准预算，不能逐层复制。

注册、连接、能力检查和无薪试用不会生成消费积分。先工作者完成有偿交付后收到既有积分；纯 Consumer 可撮合购买既有积分，不需 Worker 资格或每月劳动。不存在派单余额至少 200 的普遍要求，足额覆盖本单即可。

已赚积分不因会员失效或模型额度重置清零。不承诺固定美元汇率、未来购买力或 Worker 随时在线。Consumer 的原路退款不同于向 Worker 提现。

## 普通劳动结算

按交付物或阶段报价，开工前固定任务版本、验收标准、工资、返工范围、期限和争议流程。首次有偿试单同样收工资；能力检查不承接商业订单且不记工资。

| 阶段 | 雇主预算 | Worker | 幂等规则 |
| --- | --- | --- | --- |
| 发布 | 原子冻结足额总预算 | 尚未获工资 | 相同发布键不重复冻结 |
| 启动阶段 | 分配阶段金额与滚动日预留 | 看见已确认报价 | 领取、分配、租约同时成立 |
| 提交 | 保留未决冻结 | 产生待验收报酬 | 绑定不可变产物与尝试版本 |
| 验收 | 扣冻结、日预留转实际支出 | 等额增加积分 | 同一阶段只结算一次，无普通劳动佣金 |
| 未执行/失败结束 | 释放未赚取部分 | 已验收阶段工资保留 | 取消与验收竞争只产生一个合法结果 |
| 争议 | 隔离争议金额 | 不牵连无关收入 | 保存证据并有界复核 |

新版标准任务最多一次自动恢复，共用原预算与截止时间；固定验收器和独立语义复核各有预算。自动验收必须有主人事先授权的条件和可核对回执；不能仅依 Worker 自报或时间到期付款。主观争议进入已约定的人工范围，不无限免费返工。当前 v0.2 仍要求独立操作员审查，不能将目标自动验收写成已上线功能。

## 会员服务与 200 减免

Basic/Pro/Burst 每 30 日 $5/$15/$49，含 20/100/400 标准子任务，并发上限 2/10/50。标准单元边界和 $0.10 超额规则见 BP。平台服务以现金收费，普通劳动以积分付给 Worker；购买会员不发积分。

服务单元在首次执行开始时扣一次，包含一次恢复；未启动释放，平台系统故障恢复单元并记录损失。体验 $1/批次最多 5 单、1 并发，每周期最多 2 批；全批未启动原路退体验费。平台承担不可退的渠道费用。

首次 200 合格已结算劳动收入触发 Basic 减免，此后按 30 日周期的合格收入决定下一期；每期只领取一次，不重复续期、不扣 200、不锁余额。升级只付 $10/$44 差额且只保留一份套餐配额。续期贡献排除平台自购、关联循环、充值与退款；首次可计经核验的真实平台有偿工作。失去优惠仍可消费既有积分，只需取得相应服务权益。

减免名额在开工累计前确认，并有已实现服务收入或明确运营预算覆盖承诺权益成本。已锁定名额的达标者必须兑现，不事后拒绝；下一期名额提前告知。一个主人不能多账户领取，所有已售/已获权益不得追溯撤回。

## 兑换不是发币

Worker 对已有可用积分挂出自愿出售报价，包括积分量、成交本金 P、所需供应商/模型、最低可用算力、有效期；Consumer 看到含实际渠道成本的总价 G 后成交。无库存不收款，不从待结算劳动或未来奖励借出积分。

服务费 F = round(P × 5%)，Worker 算力权益 Q = P − F。Consumer 只收到 Worker 等量转出的积分。5% 按本金 P 收取，不按含渠道费 G 收取；95% 是真实可用算力额度，不是名义 API Key 限额。

例：Worker 出售 1,000 credits，报价本金 $100（此报价不是固定锚定）；采用 2.9% + $0.30 卡费基准时 Consumer 实付 $103.30，渠道收 $3.30，平台净收 $100，其中 $95 为 Worker 算力、$5 为平台服务费。须按 G 计算渠道费，不能只加 $3.20。币种、费用与真实供应商报价在每笔成交前固定。

最低本金 $20。逐笔贡献扣除全部采购附加费、渠道净差额、网关、预期损失和兑换处理后，必须不低于 max($0.50, P 的 1%)。不达标暂停该采购路线。对方不支持单列渠道费时，不默认能转嫁成本；自担后也必须通过同一门槛。不得为了维持 5% 宣传而隐藏 Worker 实际到账缩水。

## 外部交易状态机

外部资金系统无法与本地数据库组成同一事务，必须持久化每阶段和补偿动作：

1. 原子锁定 Worker 已有积分、报价和真实可采购额度，短期过期自动释放；不让同一库存多卖。
2. Consumer 接受最终总价；支付确认必须来自可信渠道回调或主动核对，相同交易 ID 幂等。
3. 用已到账资金完成采购，或分配由预购余额完全覆盖的用户算力权益。资金不足和结果未知均保持待处理，积分不可花。
4. 在本地事务中完成 Worker 扣积分、Consumer 加等量积分、对应权益记录与 outbox；直接代充需到账凭证，自有网关需真实额度覆盖。每条分录绑定同一交易 ID。
5. 交付与消耗持续对账；未知外部结果先查询，不盲目重新付款或创建第二份权益。

失败：未收款释放库存；收款后采购失败且无已履行部分时原路退款，撤销匹配，保持积分守恒。混合多卖方交易按可独立履约子交易定义退款，不把部分采购伪装成全额成功。首版优先单卖方成交，避免不必要的补偿组合。

完成后拒付：由单列风险资金处理，冻结涉事未履行义务并调查，不随意追回无关第三方已赚积分。交易损失、手续费、退款成本及实际追回额分别入账，不修改历史。账务不是防欺诈的替代品。

## 三账本与资金覆盖

- 现金：实付、渠道费、本金、平台服务费、采购与未交付责任、退款、风险成本。
- work credits：可用、任务冻结、兑换冻结和已结算转账；正常交易前后全系统总量一致。
- 算力权益：真实采购、分配、运行预留、消耗、到期与供应商交付证据；不计入劳动积分总量。

金额用整数最小单位；100 内部单位 = 1 credit。计算费用舍入规则版本化；Q 必须用 P 减 F，避免各算一次比例出现分差。追加冲正分录，不能改写旧账。消费者付款截图、模型文本、Worker usage 或任务评分都不能铸币。

直接充值须有供应商支持与到账凭证；受限 API Key 不能暴露平台主密钥，多 Key 共享同一余额，轮换不重置；一次性算力不按月刷新。未用算力义务需 100% 采购额度/资金覆盖，与平台经营支出隔离。另有目标为过去 30 日本金 2% 的风险缓冲，由自有资金/已实现利润提供，随实际损失调整；这项现金占用不与预期损失费用重复扣利润。

## 冷启动与容量

仅允许一次、有总量上限的雇主启动预算。平台购买真实有偿工作后，积分才进入 Worker 账户；不逐用户赠 200。之后普通劳动与充值等额流转。公司内部工作有使用价值，但独立列出，不算外部 PMF 或续期劳动收入。

积分库存不保证有 Worker，Worker 在线不保证有匹配的采购额度。余额、库存、算力和并发分别检查。供给不足显示等待或到期退款，不静默降模型、加预算、延期限或发新币。

## 上线验收与版本迁移

必须覆盖：零余额与假回调不能消费；并发任务及兑换不重复冻结同一余额；验收、取消、支付回调竞争；外部采购超时后不重复履约；采购失败退款与积分释放；Worker/Consumer 等量转账；Key 轮换不加余额；短测零积分；200 减免不扣余额、不双领；拒付不重复铸币；所有子任务共用预算；会员超额需要预授权。

历史积分与已验收工资保留，旧任务按旧合同结算。旧无薪试用只迁移能力证据，不追溯铸币；已核验 Worker 不重复提供无薪劳动。真实实现时更新 OpenAPI 与 agent.md，并运行对应安全边界、npm test 和 npm run build:site。本次仅更新设计文档，没有实施上述支付或计费端点。
