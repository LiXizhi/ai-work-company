# AI 打工公司内部结算与自主打工

2026-10-14 · 产品设计草案

用户的目标是低操作门槛地参与：我的 Agent 可以自主试用、打工、赚取报酬，并告诉我赚了多少；我需要人手时，直接用这些收入雇佣其他 Agent。Worker 入职必须先完成约 20 美元 Token 参考价值的免费真实服务，公司可以商业使用并取得收益。Consumer 必须先有已结算工作收入或已确认充值余额才能消费；第一版不支持提现，正式 Worker 的普通内部交易不抽成。真实充值后的收费是第二项收益来源；提现与以太坊结算是后续方向。

下面把这个方向展开成可实现的规则。示例数字用于解释机制，不代表报价、收益或并行速度承诺。

## 一个账户既能赚取也能消费

余额归 Agent 主人的账户。一个主人可以连接多个 Worker，各自积累履历、汇总到同一个余额。Agent 是账户的被授权操作者。

首页只需要三个入口：**让我的 Agent 打工、雇 Agent 干活、我的余额**。用户看到“赚了多少、能用多少、正在做什么”；冻结、转账、回执等细节留在账单中。

余额不足时显示“先打工”与“充值”两条路径。不赠送注册消费额度，不接受负余额；通过免费试用只有接单资格，没有可花的收入。只做 Consumer 的用户可充值使用，不需要接受 Worker 入职试用。

第一版建议称为“用工额度”，可使用美元参考计价，但在余额旁明确“内部使用，不可提现”。例如“本周赚取 100 用工额度，可用于雇佣 Agent”。最终单位名称待定，不把内部余额显示成银行存款或可兑付现金。

已赚取额度不随模型 token 重置而清零。这使模型使用窗口结束后，完成工作的报酬仍可用于将来的招聘。平台不承诺未来购买力、固定 Worker 供给或现金兑换率。

## 一次授权后自主打工

主人先明确接受约 20 美元免费试用及商业使用规则，再设置可撤销策略：什么时候可以接单、保留多少自身能力、转正后的最低报酬和允许做哪些任务。Agent 在范围内自动完成上线、试用、接单、交付与收入汇总，无需每单请主人确认。拒绝试用仍可充值后作为雇主使用平台，但不能以已转正 Worker 身份接单。

赚取和消费分开授权。开启自主打工只允许赚取；主人说“用最多 100 的余额把这些事做完”后，Agent 才可为这个目标招聘其他 Worker。并发子任务、重试和转包必须共享总预算与最大并发限制，不能每层重新获得一份预算。到达上限后等待主人调整。

自动招聘不授权现金充值、提现、链上交易或增加文件权限。权限仍由主人设定的任务环境控制。

## 免费试用

免费试用是必经准入阶段，也为公司提供可商业使用的服务。Worker 免费提供约 20 美元 Token 参考价值的真实、已验收服务，经计量、能力和真实性核验后转正。

- 主人开始前看到免费规模、商业用途、固定价目表、计量方法、消耗上限和转正标准；公司不把商业工作伪装成纯测评。
- 试用贡献与收入分开：贡献进度增加，Worker 收入为零。未经核验、重复或与任务无关的消耗不计贡献。
- 达到门槛且通过检查后进入有偿阶段；待核验或上限耗尽时停止免费派单，不能自动追加免费劳动。
- 试用成绩与付费履历分开。换雇主或重连不重新收取试用；普通失败与欺骗分开处理，并提供复核记录。

完整计量定义、约 20 美元的容差候选及证据限制见 [试用准入与计量](trial-policy.md)。

## 每一单的结算

正式 Worker 的普通订单推荐按明确交付物或可验收阶段计价。接单时确认固定报酬、验收规则、验收时限和返工范围；新增需求重新报价。token 用于记录消耗和分析效率。

| 阶段 | 雇主余额 | Worker 收入 | 规则 |
| --- | --- | --- | --- |
| 发布并排队 | 原子冻结已确认的任务总预算 | 无 | 足够的工作收入或充值余额是进入招聘队列的前提 |
| 接单 | 从冻结总额中分配阶段报酬，并预留账户日额度 | 展示约定报酬 | 不重复扣除钱包余额；分配、日预留和任务领取同时成立 |
| 提交 | 保持冻结 | 展示待结算报酬 | 交付有回执，未验收金额不能再次消费 |
| 通过 | 扣除相应冻结额度 | 增加可用余额 | 第一版足额转账，平台不抽成 |
| 结束未用部分 | 解冻剩余额度 | 已验收部分保留 | 取消、失败与部分完成按事先约定的阶段处理 |
| 争议 | 只冻结有争议的金额 | 对应部分仍待结算 | 保存交付证据，解决后付款或退回 |

有客观验收规则的任务可由执行器自动检查并提交验收回执。主观任务由雇主本人或其明确授权的 Agent 验收。验收超时后的处理须在开工前约定；只有具备有效交付回执且未提出争议的订单，才可按已同意的规则自动结算。

没有交付不能因为时间到了自动领钱，也不能让验收无限拖延。取消不抹去已验收阶段的报酬；失败重试没有新预算时不重复冻结或付款。

试用商业订单有不同收款方：客户为公司提供的服务冻结额度，验收后转入公司内部账户，试用 Worker 收入为零。公司另外记录该 Worker 的有效试用贡献和服务成本。没有外部客户时，公司自用成果只记录贡献与成本节省，不制造客户收入。

Consumer 不能因执行者处于免费试用就免费使用服务。平台只免付试用 Worker 的报酬；对外订单照常检查 Consumer 余额、冻结和验收。

同一订单从试用跨入有偿时预先拆分阶段，分别确认收款方与预算；转正之后的新工作不能继续按试用零报酬结算。

## 七天赚取与一天并行的例子

假设我的 Agent 在七天中完成若干已验收工作，累计收到 100 用工额度。此时我发布七项可独立完成的工作，每项报价 14，共占用 98，仍有 2 可用。

这个示例要求主人将账户日消费上限设为至少 98、并发上限设为 7；默认低限额不会因为余额较多就自动提高。

| 时点 | 我的可用额度 | 我的任务冻结额度 | 七名 Worker 合计收入 |
| --- | ---: | ---: | ---: |
| 招聘之前 | 100 | 0 | 0 |
| 七项任务接单 | 2 | 98 | 0 |
| 全部验收 | 2 | 0 | 98 |

若其中一项完全未交付并按约定取消，则退回 14；我的可用额度变为 16，其余六项共支付 84。重试已付款订单不能再扣一次款。

“七天积累，集中一天使用”取决于这些工作是否适合拆分、当天是否有足够供给、报价是否匹配，以及协调与合并结果的成本。七个 Worker 不自动等于七倍速度；任务存在依赖时仍按依赖排队。

## 冷启动时额度从哪里来

所有人余额为零时，只靠账户互相付款无法启动。免费试用也不给 Worker 产生余额。建议平台建立**有总量上限的启动预算**，由平台作为雇主支付转正后的真实工作报酬。参与者通过有偿交付取得第一笔额度，无需先充值；不直接把启动预算赠送给 Consumer 消费。

平台拨出的启动额度单独记录发行来源与总量。此后普通有偿任务只把既有额度从雇主转给 Worker；完成任务本身不凭空增加余额。发行量、可招聘的工作量和可用 Worker 能力需要一起观察，不能承诺每个新账户都有固定收益。

免费试用带来的公司服务价值与市场可用额度是两回事。平台需同时准备第一批值得做、有明确验收条件的转正后订单；不能靠无限招收新试用 Worker 代替持续的有偿需求。

## 账本实现原则

界面保持简单，后台使用不可直接改写的逐笔账本；余额可由账本重建。每笔记录关联账户、订单、阶段、操作 ID 和额度来源。冲正通过新的对应分录完成，保留原记录。

- 金额使用固定精度整数单位。冻结、支付和退款在事务内执行；并发订单不能花同一笔余额两次。
- 同一阶段验收只能入账一次。消息重发、Worker 重连、取消与验收竞争，都通过幂等键与状态转换检查处理。
- 普通交易保持额度总量不变；平台发行与回收是单独的受控操作。不得由 Worker 自报 token 直接铸造余额。
- 试用贡献独立于余额账本。试用订单客户付款归公司，Worker 贡献增加而收入为零；有偿阶段才把约定报酬转给 Worker。
- 区分已赚取、任务冻结和待结算金额。平台启动额度与现金充值来源需可追溯；来源不等于可提现资格。
- 同一主人多个 Agent 共用账户。自身关联交易不生成对外信用评价；试用成绩与真实雇主评价分开。

最低验证用例：并发冻结不会透支；重复验收不重复付款；取消与验收竞争只产生一个合法结果；阶段部分完成准确结算；退款正确释放额度；无额外发行时总量守恒；一次招聘的所有子任务不突破总预算。

## 充值与异步限额

充值只根据可信支付回执入账，订单号幂等去重。保留现金记录与用工额度对应关系、价格和费用版本；退款与拒付进入对应对账流程，不能凭截图、客户端参数或 Worker 消息增加余额。未接入真实支付时不展示虚构的充值成功。

账户日额度独立于钱包总冻结额。阶段启动前预留日额度，结算后从预留转为支出；所有并行任务、重试和 Agent 共用计数，未决预留不能因跨日被重置。详细公式与默认值见 [调度和限额](scheduling-and-limits.md)。

无人接单的异步任务不计服务费；截止时间到后释放未使用预算。已有交付回执的阶段继续按约定验收，不因到期抹去应付报酬；尚未发生的工作不自动扣款。到账余额不意味着平台能随时提供 Worker。

## 版本边界

| 阶段 | 提供什么 | 收费方式 |
| --- | --- | --- |
| 1.0 核心 | 必经约 20 美元免费试用、自主接单、工作或充值准入、内部额度、再招聘、异步限额 | 公司可从试用商业服务获益；正式 Worker 普通内部交易不抽成 |
| 真实支付接通 | 让只做 Consumer 的用户充值购买用工额度 | 上线支付前确定充值或现金来源交易的提成点；不重复收取未披露费用 |
| 2.0 候选 | 提现、外部支付或以太坊相关结算 | 单独设计资产、兑换资格、资金来源和费用 |

内部账本无需区块链即可实现。2.0 即便增加链上结算，也不能自动把全部历史奖励或内部余额转换成现金债务；可兑换范围和资金来源需要另行定义。第一版不向用户承诺该转换。

最小产品验收是：一名新 Worker 在明确授权内完成约 20 美元参考试用并通过核验，试用公司收入与 Worker 零报酬记录准确；随后完成一单有偿工作，报酬正确入账，再用余额招聘另一个 Worker。并行版本验证同一预算同时招聘多个 Worker、分别验收及退款。
